## In my words

Change request for the Supplier Sustainability Portal: spec v2.0 to v2.1

Context
- Pull request #4 (branch claude/affectionate-ptolemy-udznhn) holds v2.0: suppliers submit through the portal by form or workbook upload, saved to Supabase. It is NOT merged. Keep building on this branch and this pull request.
- I tested v2.0 on the Deploy Preview on 20 November 2026 (Supabase is connected to Netlify, keys start with sb_). The test found four things I want changed before merge. This is a change, so run the Tool Architect in Iteration Mode to revise docs/product-spec.md to v2.1, then the Project Governor to update CLAUDE.md, docs/checks.md and PROGRESS.md, then plan and build.

Change 1: A Path confirmation gives direction, not instructions
- Problem: after a supplier with an EcoVadis scorecard submits the short entry, it is not clear enough that they still have to share their scorecard on EcoVadis. There is too much written instruction.
- What I want: less text, one clear next step. After a successful save, the confirmation reads as "one step left": share your scorecard with The Corporate on EcoVadis, with "Go to EcoVadis" as the single, prominent action.
- Keep it a button, not an automatic redirect (pop-up blockers stop new tabs that open on their own, and a same-tab redirect takes the supplier away from the page). If the save fails, show the error and Try again and still offer the EcoVadis link, as now.
- Also shorten the A Path text before the form where possible.

Change 2: number fields must be numbers
- Problem: Scope 1 (S2-1), Scope 2 market-based (S2-2), Scope 3 (S2-3) and total water withdrawal (S4-1) accepted text, so letters were saved.
- What I want: these four fields accept a number only, enforced on the page and again in the submit function.
  - Show the unit next to each field: tCO2e for S2-1 to S2-3, m3 for S4-1.
  - Accept common formats such as 12345, 12,345 and 12345.6; refuse letters.
  - The verification method that S2-1 asks for moves to that question's evidence note.
- Upload: if a workbook has text in one of these cells, do not refuse the whole file. Show the review screen with that field marked for correction, and keep "Confirm and submit" disabled until it holds a valid number.
- Please list every other field in the 30 that the workbook marks as Quantitative, so I can decide whether the same rule applies to them.

Change 3: do not store the Excel file
- What I want: the uploaded workbook is only read to fill the review screen. The supplier can edit everything there, and the official submission is the set of answers they confirm at the end. The file itself is never saved.
- Remove file storage from the build: no upload to the submission-files bucket, file_path no longer set, and the bucket removed or left unused (recommend which, as a named migration). Update the data notice, the About page, the deletion text, docs/supabase-setup.md and docs/access-matrix.md to match.
- Delete the test files already in the bucket as part of the change.
- The route stays "upload" so we know how the answers arrived.

Change 4: no change to the supersede rule
- Submitting twice with the same company name and contact email keeps both rows; the newer is received and the older superseded. My test confirmed this works (Test B: three rows, the newest received). Keep it as is.
