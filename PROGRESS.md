## Build decisions
- Fonts load from Google Fonts only; in a blocked network the page falls back to Georgia and system sans.
- Header and nav are sticky on desktop and static on phones. Label and muted text use #6f6a5b (a darkened Stone) because Stone #B6B09F on Chalk fails AA contrast.
- Footer is Ink with Chalk text (no accent). The choice buttons show the chosen one as Ink fill.
- Governor decision: the deployed folder is site/, not the repo root, so docs/, reference/, fixtures/ and .claude/ are never served on the public URL.
- v2.0: the Backlog items for upload, storing submissions and completing the questionnaire in the page were promoted into Remaining work. Counting submissions and tracking who has responded stay on the Backlog as the dashboard.
- v2.0: supersede and insert run in one database transaction through public.create_submission (service_role only), called by the submit function; a unique index guarantees one received row per company key.
- v2.0: the platform's rls_auto_enable() event-trigger function (created with the project) is kept; its API execute was revoked.
- v2.0: refusal tests run as the anon role inside the database, so no key appears in any command.
- v2.0: the form follows the spec's question types, so S2-2 (Scope 2) stays a text field although the workbook carries a verification dropdown on E12; the reader ignores the template note pre-filled in F19; S1-3 shows only the first sentence of its workbook text.
- v2.0: S1-1 and S1-2 answers are composed by the submit function from the confirmed company and contact fields; on the form S1-3 is fixed to the workbook's "No" option.
- v2.0: the functions read the project address from SUPABASE_URL, VITE_SUPABASE_URL or SUPABASE_DATABASE_URL (the first that is an https address), and the key from SUPABASE_SERVICE_ROLE_KEY.
- v2.0: Return by email was removed (submission is through the tool), which closes the open question on its subject line.
- v2.1: the uploaded workbook is never stored; file_path stays as a column (no drop in an iteration) and a check keeps it empty; the bucket is removed by the builder in the dashboard because Supabase refuses SQL deletes of stored files (a SQL delete would orphan the files).
- v2.1: the check upload_has_file (file_path set on uploads) is replaced by file_path_unused; replacing a check is not a column drop and holds no data.
- v2.1: number answers are stored without separators ("12,345.6" as "12345.6"); a comma counts only as a thousands separator in groups of three; "12,5" is refused as ambiguous.
- v2.1: the A Path's three numbered steps and its weekly-validation line are removed from the panel; section 03 still says validations are processed weekly.
